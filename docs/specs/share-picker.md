# Share picker

Sources: standalone application [`main.ts`](../../apps/share-picker/src/main.ts), UI [`ui.ts`](../../apps/share-picker/src/ui.ts), capture/protocol/polling modules in [`apps/share-picker/src/`](../../apps/share-picker/src/).

XDPH launches a standalone GTK application, not a shell widget or settings page. Screens, Windows and All tabs show selectable sources, previews, and source identity together. Selecting a card only updates the selection summary; it never starts a stream or submits a selection. The single explicit `Compartilhar` action authorizes the selected source and is enabled only while that source is valid. Before submission it revalidates that the selected monitor/window still exists. Only then does the app write one `[SELECTION][r]/screen:NAME` or `[SELECTION][r]/window:ID` line to stdout and quit. `r` reflects the per-request restore-token checkbox/`--allow-token`; it is not a persistent shell preference. Cancel and window close quit without selection output. Preview absence does not prevent choosing a source and does not authorize transmission; requester/portal manage the session after selection.

Each screen card always identifies the source by its Hyprland output name (the exact value returned to XDPH), including in the All tab and inline selection summary; the monitor description and resolution are secondary text. Resolution labels account for 90°/270° monitor transforms, while preview images keep their captured aspect ratio and scale down inside the card and inline preview (including portrait and ultrawide outputs). A missing preview does not disable selection.

Source cards retain a stable accessible identity while their preview loads or becomes unavailable. The native source grid adapts down to one column; preview status is separate from the source name.

Live monitor refreshes keep the last successfully decoded frame visible while a new capture is in progress. A failed refresh preserves that frame and marks it discreetly as potentially outdated; the next successful capture clears the status and replaces the image. If the first capture fails before any frame exists, the picker shows unavailable rather than an empty image. Refresh failures do not trigger additional retries.

The source list and inline selection summary share the available window area; Cancel and `Compartilhar` remain in a fixed action row. Source identity is always visible alongside the selected source's preview/status; complete summary text remains available by tooltip.

The configured XDPH package passes the portal session handle as `XDPH_SESSION_HANDLE`. The picker watches the original requester's unique session-bus name, waits for its initial ownership check before enabling submission, and exits without a selection if that requester disappears. The application stays alive while awaiting the asynchronous check; shutdown removes the watch and preview resources. Malformed portal metadata fails closed. Invocations without portal metadata remain standalone protocol invocations. This handles requester disappearance; it does not claim to make XDPH's synchronous picker call generally asynchronous or fix every cancellation from a still-connected requester.
For a reported immediate re-open, the picker emits `[share-picker-trace]` lifecycle lines to stderr (PID, portal session handle, selected source kind/ID, shutdown); the selection protocol remains stdout-only. The configured XDPH patch forwards captured picker stderr into its own debug log as `[sc] Custom picker stderr`. Reproduce once from Discord or Backspace, then collect `journalctl --user -u xdg-desktop-portal-hyprland --since '5 minutes ago' --no-pager` with XDPH debug logging enabled. Correlate each `invocation`/`selected`/`shutdown` PID and session handle with XDPH `SelectSources`/`Start` request logs. One selected line followed by a second invocation in a new session indicates a requester retry/new session; repeated invocation with the same session or a missing selected line points to picker/protocol completion. Do not infer that a second invocation is safe to suppress: each portal request requires its own consent.

This trace is diagnostic, not a fix for re-opening. It does not log source titles or alter selection, restore-token behavior, or consent. The actual requester retry behavior remains unverified until correlated runtime logs are available.

Manual: invoke through XDPH on a suitable session; inspect previews/tabs, select and confirm that inline identity/preview/status update without starting transmission, then use `Compartilhar` to submit a live source and inspect stdout protocol. Cancel and close while confirming no selection line. Test stale-source rejection and restore-token request state. Proposed checks, not new VM results.
