# Screenshot and recording selection overlay

Sources: [`index.tsx`](../../packages/widgets/src/screenshot-ui/index.tsx), [`controlPanel.tsx`](../../packages/widgets/src/screenshot-ui/controlPanel.tsx), [`drawing.ts`](../../packages/widgets/src/screenshot-ui/drawing.ts), [`Screenshot`](../../packages/services/src/capture/screenshot.ts) and capture flow under `../../packages/services/src/capture/`.

The unified full-monitor overlay uses the frozen screenshot stage for screenshots, selection drawing, and a control panel. Targets include **Tela cheia**, **Área**, **Janela** and **Monitor**; recording can use a transparent live background. Choosing a target reveals the final **Capturar imagem** or **Iniciar gravação** action directly; selecting or dragging never starts capture. The action is enabled only when the target is valid and the service is not busy. Enter invokes that same action only for a valid target; busy state prevents duplicate confirmation. Escape and **Cancelar** dismiss without capture. A too-small area is invalid. The service publishes busy, result path or error for the recording-bar feedback surface. Quick mode hides mode/target selectors while retaining the same final action.

The frozen stage is the full desktop image. It is contained and centered inside the focused monitor's editing viewport (letterboxed as needed), using the bounding box of all Hyprland outputs as its global-coordinate origin. The selection canvas, window hints, monitor target and pointer use the same inverse/forward transform; selection is clamped to visible image pixels. Final crop coordinates stay in global compositor space until the capture service localizes them against the desktop bounding box and actual stage texture dimensions. This supports negative monitor origins and avoids assuming the selected monitor is the stage origin.

Window selection reads current compositor rectangles at the action boundary rather than Astal's cached positions. DrawingArea-local input is translated through the real canvas origin; area selections round global near/far edges to compositor pixels before invoking capture backends. The panel shows the actual chosen target and rectangle, or an explicit no-selection state. Changing or cancelling a selection does not commit capture.

Area selections can be resized after creation from any of the four edges or four corner handles. The pointer changes to the matching GTK resize cursor; the opposite edge remains fixed and the selected rectangle stays intact until capture.

The control panel is centered in a 480px clamp and scrolls vertically on short displays; the card styling belongs to the scrolling surface. The compact layout uses reduced spacing, with **Áudio** and **Borda da gravação** arranged horizontally for recording. The heading is **Capturar tela**, with **Imagem** and **Gravação** modes and an **O que capturar** target section. Long target summaries wrap to at most two lines with an ellipsis and a **Detalhes completos do alvo** tooltip. Monitor summaries omit the origin when it is `(0,0)`. Its input bounds follow the visible centered panel rather than stretching across the monitor, so area drags can begin outside the panel.

Screenshot completion copies PNG bytes asynchronously to the clipboard before publishing the result. The GTK main loop remains available for Wayland clipboard events; clipboard/finalization failures reach the normal capture error state.

Manual: on a suitable session select fullscreen, area, window and monitor targets; verify the final action appears immediately, remains disabled for invalid targets or while busy, and starts only on click or Enter. Drag and resize an area without starting capture; cancel and inspect that no result is emitted. Exercise error feedback using actual outcomes, inspect the produced file, and test a multi-output setup separately. These are proposed checks, not new VM results.

Manual visual/smoke check without stopping the installed shell: run the updated overlay from a build containing the current source, or use an isolated GTK harness that renders `ScreenshotOverlay` with a single app after `initSettingsRoot` and `setApp`. Do not use the installed `gapplication action` as verification: it opens the service's installed (potentially older) code. Select **Área**, drag and resize a crop, and verify neither operation starts capture and that **Capturar imagem** is already available; dismiss with Escape without capturing. For end-to-end smoke, activate the final button or Enter on a valid target and inspect the real result. Do not stop/restart the user's shell.
